Freeze

Σύνοψη & κατάσταση freeze

Το development του Workspace v1 παγώνει σε αυτό το σημείο. Το v1 καλύπτει πλήρως τα 6 αρχικά βήματα του SPEC.md (μαθητές → στόχοι → Teaching Mode ατομικό/ομαδικό → πρόοδος/ Timeline → προσχέδιο έκθεσης), εννέα επιπλέον sprints πάνω σε αυτά (Session History, «Η μέρα μου», Πρόγραμμα/ημερολόγιο, σχολικά έτη, lifecycle στόχων, κλινική εκτίμηση), μια πλήρη προαιρετική στρώση cloud-account/sync (Sprint 5A Phase 1–2), Smart Notifications engine + Notifications Inbox, πέντε release-readiness blockers με πλήρες CI hardening, και — το τελευταίο μεγάλο module πριν χαρακτηριστεί το v1.0 πλήρες — το ενιαίο Teacher Profile + Settings module (§coverage). Η πιο πρόσφατη production deploy (GitHub Actions run #30446839236, commit 5cd3d28) ολοκληρώθηκε πράσινο σε build, deploy, και post-deploy smoke — μηδέν αποτυχίες, μηδέν retries σε κανένα από τα 3 jobs.

Τι σημαίνει «freeze» εδώ

Καμία νέα λειτουργικότητα δεν ξεκινά μέχρι ρητή νέα έγκριση. Αυτό το έγγραφο είναι τεκμηρίωση only — καταγράφει την ΠΡΑΓΜΑΤΙΚΗ σημερινή κατάσταση του κώδικα, δεν αλλάζει τίποτα σε αυτόν. Το Teacher Profile + Settings module θεωρείται πλέον επίσης κλειδωμένο — καμία περαιτέρω αλλαγή/micropolishing σε αυτό εκτός αν προκύψει πραγματικό bug στη χρήση.

Θεμέλιο

Αρχιτεκτονική σύνοψη

Στοίβα

React 18 + Vite 5, react-router-dom με HashRouter (απαραίτητο για GitHub Pages — refresh/deep links χωρίς server routing), Dexie 4 πάνω από IndexedDB ως αποκλειστική πηγή αλήθειας δεδομένων, dexie-react-hooks's useLiveQuery/useObservable ως το μοναδικό reactive-data idiom (καμία Redux/Zustand — μόνο ένα React Context, για auth). PWA μέσω vite-plugin-pwa (service worker, manifest, autoUpdate). Testing: Vitest (jsdom για component tests, node για καθαρή λογική) + Playwright (production smoke, νέο στο v1). CI/CD: GitHub Actions → GitHub Pages, deploy μόνο σε push στο main.

Local-first, cloud sync προαιρετικό

Όλα τα δεδομένα ζουν στη συσκευή by default — καμία εξωτερική κλήση δικτύου πουθενά στο src εκτός του προαιρετικού Dexie Cloud addon. Το CLOUD_ENABLED feature flag (db.js) είναι η ίδια η παρουσία του VITE_DEXIE_CLOUD_URL env var· απών ⇒ η εφαρμογή λειτουργεί ακριβώς όπως ένα αμιγώς τοπικό MVP, μηδενικό cloud addon φορτωμένο καν. Όταν ενεργό, ο εκπαιδευτικός συνδέεται με email + OTP (Dexie Cloud), και μπορεί να ενεργοποιήσει ρητά συγχρονισμό μετά από μια ολοκληρωμένη migration/ ownership-verification αλυσίδα.

Dual-generation migration engine (legacy → v2)

Η πιο περίπλοκη υποδομή της εφαρμογής. Κάθε εκπαιδευτικός ξεκινά σε «legacy» γενιά (αυτο-αυξανόμενα ++id, χωρίς owner). Ενεργοποιώντας cloud sync, ένα πλήρες runMigration() αντιγράφει ΚΑΘΕ γραμμή σε παράλληλους _v2 πίνακες με deterministic id (SHA-256(userId::table::oldId), migration/deterministicId.js) — το ίδιο legacy id για τον ίδιο χρήστη παράγει πάντα το ίδιο v2 id, ώστε foreign keys να παραμένουν συνεπή χωρίς πίνακα αντιστοίχισης. Foreign keys ξαναχαρτογραφούνται ρητά (migration/foreignKeyMap.js), με resumable/idempotent ανά-πίνακα πρόοδο (migrationEngine.js) και αυστηρή τελική επαλήθευση αναφορικής ακεραιότητας (verifyMigration) πριν σημειωθεί «complete». activeTable(name) (migration/activeGeneration.js) είναι το ΜΟΝΑΔΙΚΟ σημείο δρομολόγησης legacy/v2 σε όλο τον κώδικα — καμία business-logic συνάρτηση δεν ξέρει σε ποια γενιά βρίσκεται.

Ιδιωματισμός για πίνακες με μη-id φυσικό κλειδί

domainTemplates (κλειδί: domain) και το νέο userSettings (κλειδί: key) ΔΕΝ κρατούν το φυσικό τους κλειδί ως πραγματικό primary key στη γενιά v2 — το v2 σχήμα είναι πάντα 'id, <φυσικό πεδίο>', όχι '<φυσικό πεδίο>'. Η μηχανή migration/verification υποθέτει παντού ότι το πραγματικό v2 primary key λέγεται id· ένα σχήμα που παραβίαζε αυτό θα μπλόκαρε μόνιμα, σιωπηλά, το verification για κάθε χρήστη με τέτοιο δεδομένο.

Notifications engine

Ζωντανά υπολογιζόμενες ειδοποιήσεις (goal-stale, goal-paused, near-criterion, completion-candidate, draft-report, unresolved-session) — severity/label/icon/action ΠΟΤΕ δεν αποθηκεύονται, μόνο dismiss/snooze state (notificationState/_v2, deterministic content-fingerprint id). Ένας κοινός NotificationsProvider (React Context, μία useLiveQuery κλήση μέσα στο AppShell) τροφοδοτεί Header-κουδούνι, Home-widget, και το /notifications Inbox χωρίς τριπλό υπολογισμό.

Deployment pipeline

Push στο main → GitHub Actions: npm ci → npm test (μπλοκάρει τα πάντα αν αποτύχει) → build με cloud-disabled (μόνο για το επόμενο βήμα) → Playwright pre-deploy smoke πάνω σε πραγματικό npm run preview (μπλοκάρει το deploy αν αποτύχει) → πραγματικό production build (με το πραγματικό VITE_DEXIE_CLOUD_URL repository variable) → upload artifact → GitHub Pages deploy → δεύτερο, ανεξάρτητο Playwright πέρασμα πάνω στο ήδη-δημοσιευμένο live URL.

Λειτουργικότητα

Τι καλύπτει το v1

  • Μαθητές — προσθήκη/επεξεργασία/αρχειοθέτηση, δομημένο functional profile (με υπο-ομάδες), προφίλ ενισχυτών (preferences), αρχειοθέτηση με σχολικό-έτος-aware participation tracking.
  • Στόχοι — wizard δημιουργίας, 8 τύποι μέτρησης (successRatio, promptLevel, duration, frequency, ratingScale, taskAnalysis, checklist, narrative) με ειδικό criterion panel ο καθένας, lifecycle (active/achieved/revised/archived) με ιστορικό μεταβάσεων (goalEvents), προσωπική βιβλιοθήκη προτύπων στόχων.
  • Teaching Mode — ατομικό & ομαδικό, πλήρης οθόνη χωρίς περίσπαση, καταγραφή με ένα tap, ➕ Παρατήρηση πάντα διαθέσιμη, κλινική εκτίμηση ανά στόχο/συνεδρία.
  • Συνεδρίες — Session History (αναζήτηση/φίλτρα/edit/delete), status completed/interrupted/notHeld, ανά-μαθητή απουσία, απευθείας καταγραφή notHeld χωρίς Teaching Mode.
  • «Η μέρα μου» — καθημερινή σειρά μαθητών/ομάδων, ζωντανά παραγόμενη ολοκλήρωση (καμία δική της κατάσταση), σήμα προσοχής ανά μαθητή, mood tracking.
  • Πρόγραμμα & ημερολόγιο — σταθερό εβδομαδιαίο πρόγραμμα με effective-dated εκδόσεις, εξαιρέσεις (ακύρωση/μετακίνηση), μηνιαίο ημερολόγιο, Weekly Grid προβολή, ενοποιημένη τροφοδότηση «Η μέρα μου».
  • Πρόοδος — γραφήματα ανά στόχο (recharts), σύνδεση σημείου γραφήματος ↔ συνεδρία, Timeline μαθητή (αυτόματη χρονολογική αφήγηση).
  • Εκθέσεις — persisted προσχέδιο, auto-save, preview/edit toggle, draft/final, ιστορικό ανά μαθητή, export σε .docx.
  • Σχολικά έτη — δημιουργία/μετάβαση, συμμετοχή ανά μαθητή/έτος, μαζική/ατομική μετάβαση στόχων.
  • Smart Notifications — 6 τύποι ζωντανά υπολογιζόμενων ειδοποιήσεων, Header-κουδούνι, Home-widget, πλήρες /notifications Inbox με φίλτρα severity/type/student, snooze/dismiss/unsnooze.
  • Backup/Restore — πλήρες export/import JSON, generation-aware, ownership-safe restore με auto pre-restore safety snapshot.
  • Cloud account (προαιρετικό) — email+OTP login, ξεχωριστό από ενεργοποίηση sync, πλήρης migration πριν την ενεργοποίηση, ρητή ενημέρωση+επιβεβαίωση εξουσιοδότησης πριν το sync ενεργοποιηθεί.
  • Storage Safety — navigator.storage.persist() flow με σαφή κατάσταση και μόνιμη υπενθύμιση backup.
  • Teacher Profile + Settings — ενιαίο module (όχι πια δύο άσχετες οθόνες): Settings πλέον μέσα σε <AppShell> με tabbed IA (Προφίλ εκπαιδευτικού / Λογαριασμός & Sync [μόνο όταν CLOUD_ENABLED] / Backup & Αποθήκευση / Σχολικό έτος / Εφαρμογή), compact TeacherProfileCard σύνοψη πάνω από τα tabs, ρυθμιζόμενο displayName + προαιρετικά schoolName/specialty (ίδιο userSettings table, σωστό σε τοπική & synced χρήση), disabled-until-dirty Save button, πραγματικός σύνδεσμος Header→Settings αντί για το παλιό στατικό «Εκπαιδευτικός».
  • PWA — offline-capable, εγκαταστάσιμο, service worker με auto-update.

Όρια

Τι ΔΕΝ καλύπτει ακόμη

  • End-to-end κρυπτογράφηση zero-knowledge για το cloud sync (ρητά σχεδιασμένο ως μελλοντικό βήμα στο SPEC.md — σήμερα ο συγχρονισμός είναι απλός, όχι κρυπτογραφημένος στη συσκευή πριν φύγει).
  • Portal γονέων/θεραπευτών, βιβλιοθήκη δραστηριοτήτων/Teacher Bible, AI λειτουργίες, πολλαπλές γλώσσες — ρητά εκτός MVP από το SPEC.md, παραμένουν εκτός.
  • Αυτόματη εισαγωγή επίσημων αργιών Κύπρου, εξωτερικός συγχρονισμός ημερολογίων (Google Calendar κ.λπ.), πολύπλοκα recurrence patterns.
  • Πλήρες προφίλ χρήστη — το Teacher Profile καλύπτει πλέον displayName + email (read-only) + schoolName/specialty (προαιρετικά, δεν καταναλώνονται ακόμα πουθενά αλλού) — σκόπιμα ΧΩΡΙΣ φωτογραφία, ρόλο/permissions, ή πολλαπλά σχολεία/οργανισμούς.
  • Bulk actions στο Notifications Inbox, dismissed-history, pagination/virtualization — ρητές αποφάσεις v1 σε ολόκληρο το app (καμία λίστα κάνει pagination/virtualization πουθενά).
  • Πραγματική two-device / offline↔online conflict δοκιμή για το Dexie Cloud sync — μόνο single-device συμπεριφορά έχει πραγματικά επαληθευτεί ζωντανά.
  • Πλήρες, μόνιμο browser-level (Playwright) test suite πέρα από το νέο 5-test production smoke — καμία end-to-end κάλυψη flows όπως Teaching Mode ή backup/restore σε πραγματικό browser.
  • Code-splitting/lazy-loading — ένα και μοναδικό JS bundle (~1.6MB minified) για ολόκληρη την εφαρμογή.
  • Student creation batch-flow («Αποθήκευση και νέος μαθητής») — καταγεγραμμένο, αναβεβλημένο ήδη από το SPEC.md.

Παρατηρημένο

Known limitations

ΠεριοχήΠεριορισμός
ErrorBoundary fallback shellΤο ErrorBoundary fallback screen (όχι πια το Settings.jsx, βλ. §checklist) παραμένει έξω από το <AppShell> — αποδεκτό, καθαρά «δίχτυ ασφαλείας» οθόνη, όχι κανονικό destination-route.
Bundle size~1.6MB minified / ~478KB gzip, ένα chunk, καμία code-splitting.
Storage evictionΤο Storage Safety flow ζητά persistence, αλλά ο browser μπορεί να αρνηθεί (Firefox prompt) ή να μην υποστηρίζει (παλαιότερο Safari) — η μόνη πλήρης άμυνα παραμένει χειροκίνητο backup.
Teacher Profile πεδία χωρίς καταναλωτήschoolName/specialty αποθηκεύονται/επανεμφανίζονται σωστά αλλά δεν διαβάζονται ακόμα πουθενά αλλού (π.χ. σε reports) — ρητή, εγκεκριμένη απόφαση, ΟΧΙ παράλειψη.
Global error granularityΈνα μοναδικό, top-level ErrorBoundary γύρω από όλη την εφαρμογή — ένα unhandled render error σε οποιοδήποτε σημείο ρίχνει ΟΛΟΚΛΗΡΗ την οθόνη, όχι μόνο το section που έσπασε.
Screen reader coverageΚαλή structural accessibility (focus trap, aria-pressed, semantic headings) αλλά χωρίς πλήρες NVDA/VoiceOver pass.

Δεδομένα

Backup/restore & sync assumptions

Backup/Restore

buildBackupPayload() εξάγει ΟΛΟΥΣ τους 18 MIGRATED_TABLE_NAMES πίνακες της τρέχουσας ενεργής γενιάς (legacy ή v2) κάτω από κανονικά ονόματα κλειδιών, με ρητό generation πεδίο. Το userSettings συμπεριλαμβάνεται αυτόματα (γενικός μηχανισμός, καμία ειδική περίπτωση χρειάστηκε). Restore είναι all-or-nothing μέσα σε μία transaction, με ρητό ownership-safety έλεγχο ΠΡΙΝ αγγιχτεί οτιδήποτε (v2 backup χωρίς ownership info δεν αποκαθίσταται ποτέ· backup διαφορετικού λογαριασμού σε ήδη-claimed συσκευή απορρίπτεται), και αυτόματο pre-restore safety snapshot στο appMeta πριν από κάθε καταστροφική ενέργεια.

Sync assumptions

  • Το unsyncedTables configure() είναι fail-closed by default — χωρίς ρητό localStorage hint, ΚΥΡΙΟΛΕΚΤΙΚΑ τίποτα δεν συγχρονίζεται, ούτε η υποδομή του ίδιου του addon.
  • Ενεργοποίηση sync απαιτεί: authenticated userId ταιριάζει με το claim, ολοκληρωμένο migration, ΚΑΙ ρητή, μη-persisted επιβεβαίωση εξουσιοδότησης (§checklist) σε κάθε προσπάθεια.
  • Η εναλλαγή γενιάς (legacy↔v2) απαιτεί πάντα πλήρες reload — καμία in-place αντιδραστική εναλλαγή.
  • Ανοιχτό, καταγεγραμμένο κενό: καμία πραγματική two-device ή offline→online conflict δοκιμή δεν έχει τρέξει ποτέ ζωντανά — μόνο single-device συμπεριφορά (dismiss/snooze/backup/restore/goal-deletion) έχει πλήρως QA-αρισθεί.
  • CI-side: το pre-deploy smoke build τρέχει πάντα με VITE_DEXIE_CLOUD_URL='' — ανεξάρτητο από το αν το πραγματικό repository variable είναι ρυθμισμένο, ώστε να μην εξαρτάται ποτέ από το Dexie Cloud CORS allowlist.
